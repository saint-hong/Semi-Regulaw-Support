[설계서] 구체화된 BOM 명세서 기반 규제 분석 시스템 강화

1. 개요
현재 "규제 분석" 메뉴의 BOM 입력 방식은 단일 텍스트 필드에 의존하고 있어, 분석의 정확도와 정형화된 데이터 관리에 한계가 있음. 반도체 수출입 규제(BIS EAR, ECCN 등)에 대응하기 위해 보다 세밀한 항목별 입력 시스템과 이를 반영한 분석 로직의 고도화가 필요함.

2. UI/UX 개선안
가. 입력 방식의 이원화
- '간편 입력(단일 텍스트)'과 '상세 입력(항목별 폼)' 모드 전환 기능 제공.
- 상세 입력 시, 각 항목에 대한 툴팁(도움말) 및 예시 가이드 제공.

나. 상세 BOM 입력 필드 설계
- 품목명 (Product Name): 반도체 정식 명칭
- 설계사 (Designer): 원천 기술 보유사 (미국 기술 포함 여부 확인용)
- 파운드리 (Foundry): 제조 공장 및 국가 (공정 기술 규제 확인용)
- 공정 노드 (Process Node): nm 단위 공정 (14nm/7nm/3nm 등 규제 임계값 확인)
- 주요 성능 (Key Specs): AI 연산 성능(TOPS/TFLOPS), 대역폭(Bandwidth) 등
- ECCN (Export Control Classification Number): 알고 있는 경우 입력 (예: 3A001, 3A090)
- HS Code: 수출입 통관 코드 (8542.31 등)

다. 동적 피드백 시스템
- 입력 중 특정 임계값(예: 공정 14nm 이하) 감지 시 "고위험군 공정" 알림 표시.

3. 데이터 모델 및 API 변경 (예정)
가. AnalyzeRequest 모델 확장
- 기존 `bom_item` 필드 외에 `detailed_bom` 객체 추가.
- `detailed_bom` 내부 구조: { product, designer, foundry, node, spec, eccn, hs_code }

나. 분석 로직 (Agent) 고도화
- AI 프롬프트 최적화: 구조화된 데이터를 기반으로 규제 조항(threshold)과 1:1 매칭 분석.
- 판정 근거(Basis Details) 시각화: "규제 임계값 vs 실제 사양" 비교 테이블 자동 생성.

4. 규제 분석 리포트 강화
- BOM 대조 분석 표: 사용자가 입력한 상세 사양과 관련 규제 조항의 수치적 비교를 리포트 상단에 배치.
- 위험 요소 하이라이트: 규제를 위반하거나 검토가 필요한 특정 파라미터(예: 성능 초과)를 별도 강조.

5. 기대 효과
- 규제 준수(Compliance) 정확도 향상: 텍스트 누락으로 인한 오판 방지.
- 업무 효율화: 담당자가 규제 법안의 수치와 제품 사양을 일일이 대조하는 시간 단축.
- 데이터 자산화: 정형화된 BOM 데이터를 추후 통계 및 위험 관리 대시보드에 활용 가능.
