  2. 현재 프로젝트에서 CLAUDE.md에 반영해야 할 내용

  실제 구현은 있는데 CLAUDE.md에 빠진 항목들입니다.

  실제 API 엔드포인트 구조:
  POST /api/v1/auth/login
  POST /api/v1/auth/register
  GET  /api/v1/auth/me
  POST /api/v1/analyze
  POST /api/v1/shipments
  GET  /api/v1/shipments
  PATCH /api/v1/shipments/{id}/approve
  PATCH /api/v1/shipments/{id}/logistics-done
  PATCH /api/v1/shipments/{id}/final-approve

  실제 디렉토리 구조:
  src/
  ├── agents/    (regulatory_intelligence.py, gazette_crawler.py)
  ├── api/v1/    (auth.py, analyze.py, shipments.py, health.py)
  ├── auth/      (jwt.py, rbac.py, seed.py)
  ├── middleware/ (tenant.py)
  └── models/    (user.py, shipment.py, request.py, response.py)
  frontend/
  ├── index.html, login.html, app.js, styles.css
  └── data/      (mock_companies.json, mock_bom_items.json)
  data/          (mock_regulations.json)

  실제 개발 커맨드:
  pip install -r requirements.txt
  uvicorn src.main:app --reload --port 8000
  # 또는
  bash run.sh

  실제 5부서 RBAC (법률지원부 포함):
  - 영업부, 로지스틱부, 법률지원부, 경영관리부, admin

  출하 워크플로우 (구현됨):
  PENDING → SALES_APPROVED → LOGISTICS_DONE → FINAL_APPROVED

최초 5개 아키텍쳐로 변경 또는 지금 구조 유지에 대한 의견 : 
  - 현재 상태 유지를 권장합니다. 5계층 아키텍처는 NIPA 평가용 개념적 아키텍처이지, 코드 디렉토리 구조를 그대로 따라야 하는 규칙이 아닙니다. 현재 src/agents/, src/api/, src/auth/ 구조는 MVP 규모에 깔끔하게 맞고, 아직 구현되지 않은 계층(Vector DB, MLOps, Billing)을 위해 빈 디렉토리를 만드는 건 코드베이스만 복잡하게 만듭니다.

  - 핵심 트레이드오프:

  ┌───────────┬───────────────────────────────────────────┬────────────────────────────────────┐
  │           │            5계층으로 재구조화             │             현재 유지              │
  ├───────────┼───────────────────────────────────────────┼────────────────────────────────────┤
  │ NIPA 평가 │ 디렉토리가 아키텍처 다이어그램과 일치     │ 문서(CLAUDE.md)로 이미 설명 가능   │
  ├───────────┼───────────────────────────────────────────┼────────────────────────────────────┤
  │ 개발 속도 │ 리팩토링 비용 발생, 기존 기능 일시 불안정 │ 즉시 기능 개발 계속 가능           │
  ├───────────┼───────────────────────────────────────────┼────────────────────────────────────┤
  │ 확장성    │ 구조가 먼저 있으니 컴포넌트 추가 용이     │ 새 컴포넌트 추가 시 그때 구조 도입 │
  ├───────────┼───────────────────────────────────────────┼────────────────────────────────────┤
  │ 현실성    │ 구현 없는 빈 폴더만 늘어남                │ 실제 동작하는 코드만 존재          │
  └───────────┴───────────────────────────────────────────┴────────────────────────────────────┘

  - 추천 방향: 새 기능을 구현할 때 해당 계층에 맞춰 자연스럽게 디렉토리를 추가하는 방식으로 점진적 수렴.

  - 예를 들어:
    - Vector DB 도입 시 → src/layers/data-management/ 생성
    - Billing 구현 시 → src/layers/service-architecture/billing/ 생성
    - MLOps 추가 시 → src/layers/deployment-mlops/ 생성
